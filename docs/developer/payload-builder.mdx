# Webhook Payload Builder

Hand-writing this JSON is where most first webhook attempts fail, and the failure is invisible —
a malformed alert message does not error at you, it simply never trades. Build it here instead.

## What to do with each output

**JSON payload** — the request body. Use it from a script, or as the alert message in any signal
source that lets you set one.

**TradingView alert** — paste into the alert's **Message** box, with your slot's webhook URL in
**Webhook URL**. Nothing else belongs in that box: comments, labels or stray text break the parse.

**curl** — run it directly to test. Set `METASTATION_WEBHOOK_URL` in your shell first rather than
pasting the URL inline, so it does not end up in your shell history:

```bash
export METASTATION_WEBHOOK_URL="https://metastation.fi/metastationapi/socialTrade/webhook/YOUR_SECRET"
```

:::danger Your webhook URL is a bearer credential
The token in it is the entire credential — anyone holding the URL can trade that slot. Never paste
it into a public script, a screenshot, or a shared chat. If it is exposed, press **Regenerate
Secret** in Webhook Management immediately.

→ [Secure Your Webhook](/docs/guides/secure-your-webhook)
:::

## The TradingView placeholders

Ticking **Use TradingView placeholders** swaps the symbol and side for substitutions TradingView
fills in when the alert fires:

| Placeholder | Resolves to | Works on |
|---|---|---|
| `{{ticker}}` | The chart's symbol | Any alert |
| `{{strategy.order.action}}` | `buy` or `sell` | **Strategy** alerts only |

That turns one alert into a template serving every symbol you attach it to and — for a strategy
that trades both ways — both directions. An *indicator* alert has no strategy order, so
`{{strategy.order.action}}` will not resolve there; leave the toggle off and pick a fixed side.

It changes only those two values, never the shape of the payload. **Test the concrete version
first** — a placeholder that fails to resolve produces a parse error, and a parse error is silent.

→ [More patterns: TradingView Templates](/docs/developer/tradingview-templates)

## Why the builder warns you

Some notes above the output flag payloads the parser will **reject outright**; others flag choices
that are legal but expensive when a position runs unattended:

| Warning | Why it matters |
|---|---|
| No stop loss | An automated position without one has no defined worst case |
| Cross margin | The whole slot balance backs the position, not just its margin |
| Leverage above 10x | Turns a wrong signal into a liquidation rather than a loss |
| A TP level has a price but no `amount` | The validator rejects the signal with "TPn missing price or amount" |
| TP amounts total more than the order quantity | Rejected with "Total TP amount exceeds order amount" |

→ [Risk Controls](/docs/concepts/risk-controls) · [How Orders Execute](/docs/concepts/order-execution)

## Test it before you trust it

Send one signal at a size you do not mind being wrong about, then open **Webhook Management** and
confirm it appears with a successful parse and the position you expected. Only then point a live
strategy at it.
