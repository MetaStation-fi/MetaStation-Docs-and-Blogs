# Trade from Your Own Script or Bot

**The job:** your own code decides when to trade, and MetaStation executes it. No exchange SDK,
no key management per venue, no separate integration for each exchange you use.

**You need:** a slot with automation (free on the MetaStation Account) and anything that can make
an HTTP request.

---

## The whole interface is one POST

There is no SDK to install and no session to establish. One endpoint, one method:

```
POST https://api.metastation.fi/webhook/{your-unique-token}
Content-Type: application/json
```

The token identifies the slot, so it is both the credential and the routing. Get it from
**Webhook Management → Webhook URLs**.

→ [Try it interactively in the API Reference](/docs/api/metastation-webhook-api)

## Python

```python
import os
import requests

WEBHOOK_URL = os.environ["METASTATION_WEBHOOK_URL"]

def open_position(symbol, side, quantity, stop_loss, take_profits=None):
    payload = {
        "action": "open",
        "symbol": symbol,
        "side": side,
        "orderType": "market",
        "quantity": quantity,
        "category": "linear",
        "leverage": 5,
        "marginMode": "isolated",
        "futurestopLoss": {
            "slType": "market",
            "stopLossPrice": stop_loss,
            "priceType": "mark",
        },
    }
    if take_profits:
        payload["takeProfits"] = take_profits

    response = requests.post(WEBHOOK_URL, json=payload, timeout=10)
    response.raise_for_status()
    return response.json()


result = open_position(
    symbol="BTCUSDT",
    side="buy",
    quantity=0.01,
    stop_loss=41000,
    take_profits=[
        {"price": 48000, "amount": 0.005},
        {"price": 52000, "amount": 0.005},
    ],
)

if not result.get("success"):
    print("rejected:", result.get("code"), result.get("message"))
```

:::danger Never hardcode the webhook URL
It is a bearer credential — holding it is sufficient to trade the slot. Read it from an
environment variable or a secret store. A URL committed to a repository is a URL that will
eventually be found, and public code search finds them faster than you would expect.
:::

## Node.js

```javascript
const WEBHOOK_URL = process.env.METASTATION_WEBHOOK_URL;

async function openPosition({symbol, side, quantity, stopLoss, takeProfits}) {
  const response = await fetch(WEBHOOK_URL, {
    method: 'POST',
    headers: {'Content-Type': 'application/json'},
    body: JSON.stringify({
      action: 'open',
      symbol,
      side,
      orderType: 'market',
      quantity,
      category: 'linear',
      leverage: 5,
      marginMode: 'isolated',
      futurestopLoss: {slType: 'market', stopLossPrice: stopLoss, priceType: 'mark'},
      ...(takeProfits && {takeProfits}),
    }),
  });

  if (!response.ok) {
    throw new Error(`HTTP ${response.status}`);
  }
  return response.json();
}
```

## Handle the response, don't assume it

A rejected signal returns `"success": false` with a `code`. **A script that fires and forgets will
believe it is in a position it does not have** — which is how a strategy ends up doubling down on
a trade that never opened.

At minimum:

```python
if not result.get("success"):
    log.error("signal rejected: %s %s", result.get("code"), result.get("message"))
    # do NOT update local position state here
```

→ [Error Codes](/docs/developer/error-codes)

## The three actions

| Action | Use |
|---|---|
| `open` | New position |
| `close` | Close fully, or partially with `quantity` |
| `update` | Change TP/SL on an open position |

:::note There is no `reverse` action
The API rejects it: `Invalid action: reverse. Must be one of: open, close, update, cancel`. A
strategy that flips on signal sends a `close` followed by an `open`.
:::

→ [Supported Actions](/docs/developer/supported-actions)

## Mistakes that cost money

| Mistake | Consequence |
|---|---|
| No stop loss in the payload | An unbounded worst case on a position nobody is watching |
| TP `amount` as a percentage | Rejected — `amount` is a token quantity, and totals above `quantity` are rejected too |
| Percentage sizing with a compounding bug | `"2%"` recalculates on each signal. A retry loop compounds into a much larger position than intended |
| Retrying on timeout without checking | A timeout is not a rejection. The order may have executed — verify before resending |
| Ignoring `success: false` | Local state diverges from reality |
| Cross margin by default | One bad signal can take the account, not just the position |
| No rate limit on the slot | A loop bug becomes dozens of positions before you notice |

The retry case deserves care. A network timeout tells you nothing about whether the request was
processed. Check the actual position state before sending the order again.

## Before it runs unattended

1. Test each signal path against a small size and confirm it in **Webhook Management**.
2. Set a **rate limit** on the slot so a loop bug is bounded.
3. Set **max open positions** so a stuck condition opens one position, not forty.
4. Add an **IP whitelist** for your server's address — this makes a leaked URL unusable to anyone
   else.
5. Verify your error path by sending a deliberately malformed payload and confirming your code
   handles the rejection.
