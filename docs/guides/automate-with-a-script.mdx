# Trade from Your Own Script or Bot

**The job:** your own code decides when to trade, and MetaStation executes it. No exchange SDK,
no key management per venue, no separate integration for each exchange you use.

**You need:** a slot with automation (free on every MetaStation Account) and anything that can make
an HTTP request.

---

## The whole interface is one POST

There is no SDK to install and no session to establish. One endpoint, one method:

```
POST https://metastation.fi/metastationapi/socialTrade/webhook/{your-webhook-secret}
Content-Type: application/json
X-MetaStation-Signature: t=<unix seconds>,v1=<hex>
```

The secret in the URL identifies the slot. Copy the URL from **Automation → Your Webhook URLs**.

---

## Step 1 — Turn on signed requests

A script can sign, so make it: on the Automation page, press **Generate signing key** on the slot.
The key is shown **once** — put it in an environment variable or secret store. From then on the slot
refuses unsigned requests, so a leaked URL is useless without the key.

The signature is `v1` = HMAC-SHA256 of `"<t>.<raw body>"` with the signing key, where `t` is the
current unix time in seconds. It must arrive within 300 seconds of `t`, and is accepted once.

→ [Secure Your Webhook](/docs/guides/secure-your-webhook)

## Python

```python
import hashlib, hmac, json, os, time
import requests

WEBHOOK_URL = os.environ["METASTATION_WEBHOOK_URL"]
SIGNING_KEY = os.environ["METASTATION_SIGNING_KEY"]


def send(signal, dry_run=False):
    # Sign the exact bytes you send: never re-serialise the body after signing.
    body = json.dumps(signal)
    t = str(int(time.time()))
    v1 = hmac.new(SIGNING_KEY.encode(), f"{t}.{body}".encode(), hashlib.sha256).hexdigest()
    url = WEBHOOK_URL + ("?dryRun=1" if dry_run else "")
    response = requests.post(
        url,
        data=body.encode(),
        headers={
            "Content-Type": "application/json",
            "X-MetaStation-Signature": f"t={t},v1={v1}",
        },
        timeout=10,
    )
    return response.status_code, response.json()


status, result = send({
    "action": "open",
    "symbol": "BTCUSDT",
    "side": "buy",
    "orderType": "market",
    "quantity": 0.01,
    "category": "linear",
    "leverage": 5,
    "marginMode": "isolated",
    "futurestopLoss": {"slType": "market", "stopLossPrice": 41000, "priceType": "mark"},
    "takeProfits": [
        {"price": 48000, "amount": 0.005},
        {"price": 52000, "amount": 0.005},
    ],
})

if not result.get("success"):
    print("refused:", status, result.get("message"))
```

:::danger[Never hardcode the URL or the key]
Read both from environment variables or a secret store. A URL or key committed to a repository will
eventually be found, and public code search finds them faster than you would expect.
:::

## Node.js

```javascript
// Node 18 or later.
const crypto = require('node:crypto');

const url = process.env.METASTATION_WEBHOOK_URL;
const key = process.env.METASTATION_SIGNING_KEY;

async function send(signal) {
  // Sign the exact string you send: never JSON.stringify the signal a second time.
  const body = JSON.stringify(signal);
  const t = Math.floor(Date.now() / 1000);
  const v1 = crypto.createHmac('sha256', key).update(`${t}.${body}`).digest('hex');
  const response = await fetch(url, {
    method: 'POST',
    headers: {'Content-Type': 'application/json', 'X-MetaStation-Signature': `t=${t},v1=${v1}`},
    body,
  });
  return {status: response.status, result: await response.json()};
}
```

## curl, for testing

```bash
BODY='{"action":"open","symbol":"BTCUSDT","side":"buy","orderType":"market","quantity":0.001}'
T=$(date +%s)
SIG=$(printf '%s' "$T.$BODY" | openssl dgst -sha256 -hmac "$METASTATION_SIGNING_KEY" | sed 's/^.* //')
curl -sS -X POST "$METASTATION_WEBHOOK_URL?dryRun=1" \
  -H 'Content-Type: application/json' \
  -H "X-MetaStation-Signature: t=$T,v1=$SIG" \
  --data-binary "$BODY"
```

`?dryRun=1` returns what would be placed and places nothing — drop it to trade.

## Handle the response, don't assume it

A refused signal returns `"success": false` with a `message`, and an HTTP status that says what kind
of refusal it is. **A script that fires and forgets will believe it is in a position it does not
have** — which is how a strategy ends up doubling down on a trade that never opened.

```python
if not result.get("success"):
    log.error("signal refused: %s %s", status, result.get("message"))
    # do NOT update local position state here
```

A `200` means **queued**, not filled. Confirm the position from the exchange, or from **History →
Signal History**.

→ [Error Codes](/docs/developer/error-codes)

## Retries are safe

The same request sent again within **60 seconds** runs **once**: the second answer carries the first
signal's id and `"replay": true`. So on a timeout, resend the **same body** — do not build a new one.
After 60 seconds, check the position before sending again.

## The actions

| Action | Use |
|---|---|
| `open` | Open, or add to, a position |
| `close` | Close fully, or partially with `quantity` |
| `target` | Say what to hold — `long`, `short` or `flat`. One message flips a position |
| `cancel` | Withdraw followers' resting copy entries |

There is no `reverse` action — use `target`. Do not use `update` to move a stop: it does not modify
an open position's protection.

→ [Supported Actions](/docs/developer/supported-actions)

## Mistakes that cost money

| Mistake | Consequence |
|---|---|
| No stop loss in the payload | An unbounded worst case on a position nobody is watching |
| TP `amount` as a percentage | Rejected — `amount` is a token quantity |
| Re-serialising the body after signing | The signature no longer matches; every request is refused with `401` |
| Sending a stale `timestamp` | An opening signal more than 90 seconds old is refused |
| Building a new body for a retry | It is a new signal, not a retry — it can open a second position |
| Ignoring `success: false` | Local state diverges from reality |
| Cross margin by default | One bad signal can take the account, not just the position |
| No Trade Setting on the slot | Nothing caps the leverage or size a buggy signal asks for |

## Before it runs unattended

1. Send each signal path with `?dryRun=1`, then once at a small size, and confirm it in **History →
   Signal History**.
2. Set the slot's **Trade Setting** — a leverage cap and a size cap — so a bug is bounded.
3. Use **Signed requests**, so a leaked URL is useless.
4. Verify your error path by sending a deliberately malformed payload and confirming your code
   handles the refusal.
