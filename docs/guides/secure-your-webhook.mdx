# Secure Your Webhook URL

**The thing to understand first:** on the default mode, **URL only**, your webhook URL is a **bearer
credential**. Anyone who has the URL can open and close positions on that slot.

```
https://metastation.fi/metastationapi/socialTrade/webhook/{your-webhook-secret}
```

The fix is to make the URL **not enough on its own**. Every slot can do that.

---

## Choose a verification mode

On **Automation → Your Webhook URLs**, each slot has a verification mode:

| Mode | A request is accepted when… | Use it for |
|---|---|---|
| **URL only** | It has the URL | Quick tests only |
| **Signed requests** | It carries a valid signature made with your **signing key** | Your own scripts, bots and servers |
| **Source-address check** | It comes from TradingView's published addresses | TradingView alerts, which cannot sign |

With either of the last two, a leaked URL is a useless string for anyone else. Real-money followers
can only copy a provider's product once its webhook uses one of them.

### Signed requests

1. Press **Generate signing key** on the slot. It is shown **once** — store it as you would a
   password. Unsigned requests to the slot are refused from then on
2. Sign every request: `X-MetaStation-Signature: t=<unix seconds>,v1=<hex>`, where `v1` is the
   HMAC-SHA256 of `"<t>.<raw body>"` with the signing key
3. Send it within **300 seconds** of `t`. A signature is accepted **once** — a replayed request is
   refused

The Automation page's **How to sign a request** shows ready code in curl, Node.js and Python.
→ [Automate with a Script](/docs/guides/automate-with-a-script)

### Source-address check

Pick it for a slot driven by TradingView alerts. Requests from anywhere else are refused, so a leaked
URL cannot be used from another machine.

Every refusal by the verification mode answers `401`, *"This webhook request was not accepted."*,
and you get a notice in the app — at most once a minute — saying what failed.

## Where URLs leak from

Ranked by how often it actually happens:

1. **A screenshot.** Someone shares their Automation screen for support and the URL is readable in
   it. The page hides the URL until you press **Show the webhook URL** for this reason.
2. **A public TradingView script.** Pine scripts published with the URL in a comment or default.
3. **A committed config file.** `.env` files pushed to a repository; public code search finds
   these very quickly.
4. **A shared chat.** Pasted into a Telegram or Discord group while asking for help.
5. **A support request to anyone but MetaStation.** No legitimate support process needs it.

---

## Bound what any signal can do

Set the slot's **Trade Setting** — a maximum leverage and a maximum size. It caps *every* signal,
whoever sent it. A leaked URL against a slot capped at 5x and 2% of balance is a much smaller
problem than one against an uncapped slot.

The platform also limits every webhook to 300 requests a minute per address and 120 a minute per
slot, refuses opening signals more than 90 seconds old, and runs a repeated request only once.

→ [Risk Controls](/docs/concepts/risk-controls)

---

## Regenerate the moment there is doubt

**Automation → Your Webhook URLs → Regenerate Secret** on the affected slot (at most once every 24
hours).

The old URL stops working immediately. Then update every legitimate sender — TradingView alerts,
scripts, anything else pointed at it — because they are now sending to a dead endpoint.

Do this if the URL has been in a screenshot, in a repository, in a chat, on a machine you no
longer control, or if you simply cannot account for everywhere it has been.

---

## If you think it has been used

1. **Regenerate the secret** — stop the bleeding first.
2. **Switch the slot to Signed requests** or the **Source-address check**.
3. **Check open positions** on that slot and close anything you did not open.
4. **Read History → Signal History.** Every received signal is recorded, so you can see exactly what
   was sent and when.
5. **Check the other slots.** Each slot has its own URL, so one leak does not compromise the
   others — but confirm rather than assume.
6. **Check your account itself.** A leaked webhook URL does not expose your login, but if you are
   unsure how it leaked, change your password and **Sign out everywhere**.

:::note[What a leaked webhook URL cannot do]
It cannot withdraw funds. Every withdrawal is confirmed with a 6-digit code from your authenticator
app or your inbox, which the webhook endpoint cannot reach. The damage from a leaked URL is trading
damage, bounded by the slot's Trade Setting.
:::

→ [Withdrawal Security](/docs/security/withdrawal-whitelist)

---

## Habits worth having

| Do | Instead of |
|---|---|
| Use Signed requests or the Source-address check | Relying on the URL staying secret |
| Read the URL and signing key from environment variables | Hardcoding them in a script |
| Redact the URL before any screenshot | Trusting that nobody will read it |
| Use a separate slot for experiments | Testing against the slot holding your capital |
| Regenerate on staff or device changes | Waiting for evidence of misuse |
