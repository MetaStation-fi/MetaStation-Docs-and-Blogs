# Send TradingView Alerts to Binance Automatically

**The job:** a TradingView indicator or strategy fires an alert, and a trade opens on your
Binance account — sized, leveraged and protected — with nobody watching the chart.

**Time:** about 15 minutes. **You need:** a TradingView plan that includes webhooks (any paid
tier), a Binance account, and a MetaStation account.

:::info[Binance needs a plan; the native account does not]
Webhook automation on a connected Binance, ByBit or KuCoin slot requires a plan for that slot from
the Store. It is **free on your MetaStation Account slot**. If you are here to test whether
webhook automation suits you, run this guide against the MetaStation Account first — every step is
identical except the slot you pick — and connect Binance once you know you want it.
:::

---

## Step 1 — Connect Binance

Generate an API key at Binance and add it to MetaStation. The permissions to grant are trading
permissions only, and **withdrawals must stay disabled** — MetaStation never needs them, so a
compromised key cannot move funds off your exchange account.

Follow [Connect an Exchange](/docs/trading/connect-exchange) for the key generation and the exact
fields, then return here.

## Step 2 — Unlock automation on the slot

Open **Store** in the sidebar ([metastation.fi/store](https://metastation.fi/store)), pick the
Binance **Slot**, pay with a MetaStation Account (the Store charges USDC), and confirm. Tick **Renew
automatically** if you want it to continue.

Until this is done, the slot's row on the Automation page reads **Not purchased**, and its webhook
answers `403`.

## Step 3 — Copy the webhook URL and lock it to TradingView

Open **Automation** → **Signal sources**
([metastation.fi/social-trade/automation](https://metastation.fi/social-trade/automation)).

Under **Your Webhook URLs**, find the Binance slot, press **Show the webhook URL** and copy it:

```
https://metastation.fi/metastationapi/socialTrade/webhook/{your-webhook-secret}
```

Then set the slot's verification mode to **Source-address check**. Requests are then accepted only
from TradingView's published addresses, so a leaked URL is useless to anyone else.

:::danger[Treat the URL as a password anyway]
Do not paste it into a public TradingView script, a screenshot, or a shared chat. If it leaks,
press **Regenerate Secret** — the old URL stops working immediately.
:::

## Step 4 — Set the slot's Trade Setting first

Do this **before** the first alert fires, not after. Press **Trade Setting** on the slot:

| Control | Suggested first value |
|---|---|
| Leverage | 3x–5x |
| USD in Value, or Percentage of Balance | 1–2% of balance |
| Use this as maximum risk setting | On |

A signal asking for more is cut down to these caps. A signal with no size uses them as its size.

→ [Risk Controls](/docs/concepts/risk-controls)

## Step 5 — Create the TradingView alert

On your chart, open the indicator or strategy, click the clock icon, and create an alert.

1. **Condition** — your strategy's entry condition.
2. **Alert actions** — tick **Webhook URL** and paste the URL from Step 3.
3. **Message** — this is the payload. Paste the JSON below.

```json
{
  "action": "open",
  "symbol": "BTCUSDT",
  "side": "buy",
  "orderType": "market",
  "quantity": 0.01,
  "category": "linear",
  "leverage": 5,
  "marginMode": "isolated",
  "futurestopLoss": {
    "slType": "market",
    "stopLossPrice": 41000,
    "priceType": "mark"
  },
  "takeProfits": [
    { "price": 47000, "amount": 0.005 },
    { "price": 50000, "amount": 0.005 }
  ]
}
```

Three things about this payload are deliberate:

- **`marginMode: "isolated"`** bounds the worst case to this position instead of the account.
- **The stop loss is in the payload**, not added by hand afterwards. Anything you plan to add
  manually depends on you being awake.
- **Take-profit `amount` values are token quantities** and total exactly the order quantity.
  Percentages and keywords are rejected by the API.

### Making it follow the chart

For a strategy, one alert can do everything. Send the position the strategy **wants to hold**:

```
{
  "symbol": "{{ticker}}",
  "market_position": "{{strategy.market_position}}",
  "position_size": {{strategy.market_position_size}},
  "timestamp": "{{timenow}}"
}
```

`long`, `short` and `flat` open, flip and close the position. Because it says what to *hold*, an
alert that fires twice does nothing the second time, and a missed alert heals on the next one.

→ More patterns in [TradingView Templates](/docs/developer/tradingview-templates)

## Step 6 — Test before you trust it

First a dry run — it shows what would be placed and places nothing:

```bash
curl -X POST "$METASTATION_WEBHOOK_URL?dryRun=1"   -H "Content-Type: application/json"   -d '{"action":"open","symbol":"BTCUSDT","side":"buy","orderType":"market","quantity":"1%","leverage":3,"marginMode":"isolated"}'
```

If the slot is on the Source-address check, run the dry run before switching it on, or fire the
alert from TradingView instead.

Then fire one real alert at a size you do not mind being wrong about, and check **History → Signal
History** — the signal should appear with its **Processing Status**. Confirm the position exists on
Binance, at the size and leverage you expected — **including its stop-loss order** — then close it.

Only after that should you let the strategy run live.

## Step 7 — Close the loop

An entry alert without an exit leaves positions open indefinitely. With the target template above,
`flat` closes the position. With separate alerts, create an exit alert with:

```json
{
  "action": "close",
  "symbol": "{{ticker}}"
}
```

Omitting `quantity` closes the whole position. Include `"quantity": "50%"` to scale out instead.

## When it does not work

| Symptom | Cause |
|---|---|
| The alert gets `403` | The slot has no active plan — Step 2 |
| The alert gets `401` | The Source-address check refused it — it did not come from TradingView |
| The alert gets `404` | The URL is out of date — the secret was regenerated |
| The alert gets `400` | The message is not valid JSON. TradingView comments and stray text break it |
| Listed in Signal History but not executed | Its **Reason** says why — a late signal, no size, or the exchange refused it |
| Executed at an unexpected size | Check which size form the payload used, and the slot's Trade Setting caps |

The order of that table matches the [signal pipeline](/docs/concepts/signal-pipeline) — the first
row that matches is your answer.
