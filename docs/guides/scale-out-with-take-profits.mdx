# Scale Out of a Trade with Multiple Take Profits

**The job:** stop choosing between taking profit too early and watching a winner round-trip. A
ladder closes slices of the position at rising levels while the rest keeps running.

**You need:** any MetaStation slot. Up to **10** levels per position.

---

## What a ladder actually changes

Worth being clear before building one, because it is commonly oversold.

A ladder **does not improve your edge**. It changes the *shape* of the outcome: you give up part
of the best case in exchange for banking some of the move earlier and reducing the chance of a
winner becoming a loser. That is a preference about how you want to be wrong, not a better
strategy.

If your strategy's returns come from a few very large moves, laddering out early will reduce
total return. If it grinds small moves and gives them back, laddering will help. Know which one
you have.

---

## Step 1 — Place the levels where price actually goes

Levels should sit at prices the market plausibly reaches, not at round numbers or equal
increments. Structure — prior highs, range boundaries, measured moves — beats arithmetic.

A ladder whose top rung is never touched is a ladder with fewer rungs than you designed.

## Step 2 — Split the size deliberately

Three common shapes, and what each says:

| Shape | Split | Says |
|---|---|---|
| **Front-loaded** | 50 / 30 / 20 | Bank early, protect the win. Best when reversals are common |
| **Even** | 33 / 33 / 34 | No opinion about where the move ends |
| **Back-loaded** | 20 / 30 / 50 | The thesis is the big move; early exits are just insurance |

Front-loaded is the conservative default because the first level is the one most likely to fill.

**Over the webhook API, each level needs an `amount` in base tokens**, and the totals must not
exceed the order quantity — the signal is rejected otherwise. In the terminal you can enter a
token amount, a USD value or a percentage.

## Step 3 — Build it in the terminal

1. In the order panel, expand **Take Profit**.
2. Click **+ Add TP**.
3. Set price and quantity per level — token amount, USD, or percentage.
4. Confirm. The orders are placed as the position opens.

{/* SCREENSHOT: guide-tp-ladder | order panel with a three-level TP ladder configured | 1440x900 | redact: balance */}

Worked example — long from $45,000:

| Level | Price | Slice |
|---|---|---|
| TP1 | $48,000 | 30% |
| TP2 | $50,000 | 40% |
| TP3 | $52,000 | 30% |

Price reaching $48,000 closes 30%. If it then reverses, **TP2 and TP3 stay open** — they are not
cancelled and have not been missed. They simply have not triggered.

## Step 4 — Or send it in the payload

For automated entries, the ladder travels with the signal:

```json
{
  "action": "open",
  "symbol": "BTCUSDC",
  "side": "buy",
  "orderType": "market",
  "quantity": 0.01,
  "category": "linear",
  "leverage": 5,
  "marginMode": "isolated",
  "takeProfits": [
    { "price": 48000, "amount": 0.003 },
    { "price": 50000, "amount": 0.004 },
    { "price": 52000, "amount": 0.003 }
  ],
  "futurestopLoss": {
    "slType": "market",
    "stopLossPrice": 41000,
    "priceType": "mark"
  }
}
```

The stop loss belongs in the same payload. A ladder manages the upside; without a stop, the
downside is unbounded.

→ [JSON Format](/docs/developer/json-format)

## Step 5 — Pair it with SLX

A ladder plus a static stop still lets a trade that hit TP1 come all the way back to a loss on
the remainder. SLX fixes exactly that: after TP1 fills, move the stop to entry.

```json
{
  "stopLossX": {
    "slxMode": "trailing_profits",
    "activationPoint": "TP1",
    "trailingType": "breakeven"
  }
}
```

This is the combination most people actually want.

→ [Make a Trade Risk-Free with SLX](/docs/guides/risk-free-trade-with-slx)

---

## Adjusting a live ladder

Send an `update` to change protection on an open position:

```json
{
  "action": "update",
  "symbol": "BTCUSDC",
  "takeProfit": 51000,
  "stopLoss": 44000
}
```
