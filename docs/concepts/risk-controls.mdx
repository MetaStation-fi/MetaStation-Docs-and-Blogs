# Risk Controls

Automation removes the pause where a human would have said "that looks wrong". The controls below
are what replace it. They are the only thing standing between a malformed signal at 3am and your
balance.

**Most of them are off until you set them.** The few that are always on are marked.

---

## The layers

Limits live at five levels, and they compose — a trade must pass all of them.

| Layer | Controls | Applies to |
|---|---|---|
| **Account** | Authenticator, withdrawal confirmation code, dead man's switch | Everything |
| **Slot** | **Trade Setting**: leverage cap, size cap, default size | Every signal the slot executes — webhook and Telegram |
| **Signal source** | Webhook verification mode; Telegram sender filter; platform limits | Signals from that source |
| **Copy subscription** | Loss stops, daily loss limit, markets and direction, position caps, take-profit and stop-loss overrides | Trades copied from one provider |
| **Position** | Stop loss, take-profit ladder, SLX | One trade |

---

## Slot level: Trade Setting

Open **Automation → Your Webhook URLs**, and press **Trade Setting** on the slot. It caps what any
signal on that slot can do:

| Setting | Range | What it does |
|---|---|---|
| **Leverage** | 0–100× | A signal asking for more is executed **at the cap**, not rejected |
| **Percentage of Balance (%)** | 0–100 | A signal sized above it is cut down to it |
| **USD in Value** | 0 or more | A signal sized above it in USD is cut down to it |
| **Use this as maximum risk setting** | On / off | Turns the caps on |

When a signal names **no size**, the slot's percentage or USD value is used as its size. A **close**
that names no size closes the whole position.

Leverage is the highest-value single setting available: it is what turns a wrong signal into a
liquidation instead of a loss.

## Signal-source level

### Webhook verification mode

Each slot's webhook URL has one of three checks, set in **Automation**:

| Mode | What it accepts |
|---|---|
| **URL only** | Anyone who has the URL. Works with every sender |
| **Signed requests** | Only requests signed with your signing key (`X-MetaStation-Signature`). Unsigned requests are refused |
| **Source-address check** | Only requests from the published addresses of the charting alert service. For TradingView alerts, which cannot sign |

**Regenerate Secret** invalidates the old URL immediately (at most once every 24 hours). Use it the
moment a URL has been pasted anywhere you would not paste a password.

→ [Secure Your Webhook](/docs/guides/secure-your-webhook)

### Telegram sender filter

Each connected channel has **Who can trigger trades**: anyone who posts, channel admins only, bots
only, or pinned messages only. Narrowing it to admins or pinned messages stops a stray reply from
being read as a signal. A channel can also be **paused** — new signals are ignored until you resume
it.

### Always on: platform limits

| Limit | What happens |
|---|---|
| **Stale signals** | An opening signal more than **90 seconds** old when it arrives is refused, not traded. Closes are never refused for age |
| **Duplicates** | The same request repeated within **60 seconds** runs once |
| **Rate limits** | Per IP and per slot. Above them the webhook answers `429` with a `Retry-After` |

## Copy-subscription level

When you copy a provider, the copy settings are the controls between their trades and your
balance:

- **Stop after a loss** in USD, or a **trailing stop** on the copy's value — with a choice of what
  happens to open positions: close them, keep them, or close them with the provider
- A **daily loss limit**
- **Only these / all but these** markets, and **long only / short only**
- Caps on **open positions**, **margin per market** and **total margin**
- **Take profit and stop loss** in ROI % or USD, applied to every copied trade
- **Copy only trades with a stop-loss**

→ [Copy Settings](/docs/social-trading/copy-settings)

## Position-level protection

A stop loss is not a risk control you configure once. It is per-trade, and a position without one
has an undefined worst case.

For automated strategies, attach protection **in the signal itself** rather than adding it by
hand afterwards. Anything added manually depends on you being awake:

```json
{
  "action": "open",
  "symbol": "BTCUSDC",
  "side": "buy",
  "quantity": 0.01,
  "category": "linear",
  "leverage": 5,
  "marginMode": "isolated",
  "futurestopLoss": {
    "slType": "market",
    "stopLossPrice": 41000,
    "priceType": "mark"
  },
  "takeProfits": [
    { "price": 47000, "amount": 0.005 },
    { "price": 50000, "amount": 0.005 }
  ]
}
```

`marginMode: "isolated"` belongs in that payload for the same reason: it bounds the loss to the
position rather than the account.

When a signal's entry is a resting limit order, its stop and take-profits are placed **when the
entry fills**, sized to the fill. If a stop cannot be placed, the position is closed rather than
left unprotected.

→ [Order Execution](/docs/concepts/order-execution)

---

## Account level: the dead man's switch

Opt-in, per account: if MetaStation loses contact with the exchange for 5 minutes, the exchange
cancels every resting order on the account. It protects against orders filling while we are
unreachable — and it removes your stop-losses too.

→ [Dead Man's Switch](/docs/security/dead-mans-switch)

---

## A defensible starting configuration

For a signal source you have not yet verified with real money:

| Control | Starting value | Why |
|---|---|---|
| Leverage cap | 3x–5x | Survive being wrong |
| Size cap | 1–2% of balance, or a fixed USD value | Constant risk, no compounding into a bad run |
| Webhook mode | Signed requests, or Source-address check for TradingView | A leaked URL stops being usable |
| Telegram sender | Channel admins only | A reply is not a signal |
| Margin mode | Isolated | Worst case is knowable in advance |
| Stop loss | In every payload | A position without one has no defined worst case |

Loosen these once a source has proven itself over a real sample. Tightening them after a loss is
the expensive order to do it in.
